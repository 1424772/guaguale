# 排行榜与游戏记录 v0.1

> 状态：已实现，2026-09-16。

## 1. 财富排行榜

- 数据源始终是 MySQL `users.balance`，Redis 只保存前 100 名的 8 秒快照，不作为金币真相来源。
- 排序规则依次为：当前余额降序、达到当前余额的时间升序、用户 ID 升序。
- `users.balance_ranked_at` 在每次购卡、兑奖、每日奖励、洗盘子奖励和道具升级导致余额变化时更新。
- 接口返回前 100 名、当前玩家的实时名次、总玩家数、榜单生成时间和是否命中缓存。
- 当前玩家名次每次都从 MySQL 实时计算，即使前 100 名来自 Redis 快照也不会返回过期的个人名次。
- Redis 不可用或读取失败时自动查询 MySQL，排行榜故障不影响注册、购卡和兑奖主流程。
- 对外仅返回脱敏用户名：保留首尾字符，中间以星号替代；用户 ID 不进入 HTTP JSON。
- 首版排行榜只展示当前财富，不发排名奖励，也不按购卡或道具消费额积分。

接口：

```text
GET /api/v1/leaderboard
```

## 2. 游戏记录

- 游戏记录由不可删除的卡片生命周期字段生成，首版接口返回最近 100 条事件。
- 支持的事件类型：`purchase`、`scratch`、`robot`、`redeem`、`discard`。
- 免费转盘卡记录为“每日转盘获得”，金币变化为 0；付费购卡显示实际支付金币。
- 手动刮奖和机器人刮奖分开记录。机器人中奖时合并显示“自动刮奖并兑奖”，避免同一动作重复展示。
- 未刮卡丢弃时不读取、不返回隐藏结果；已刮中奖卡未兑奖即丢弃时明确记录损失的虚拟金币金额。
- `tickets.scratch_source` 保存 `manual` 或 `robot`，保证 API 重启后仍能准确还原机器人历史。
- MySQL 永久保存卡片及时间戳，前端只限制单次显示数量，不删除历史数据。

接口：

```text
GET /api/v1/history
```

## 3. 前端

- PC 顶栏增加“排行榜”和“记录”入口。
- 手机端顶栏换为两行布局，五个主入口均可直接点击，不隐藏排行榜和记录。
- 排行榜弹窗包含前三名展示、可滚动前 100 名列表和固定的本人排名信息。
- 游戏记录弹窗支持全部、获得/购买、手动刮奖、机器人、兑奖、丢弃六种筛选。

## 4. 验收点

1. 同余额玩家排名稳定，先达到当前余额者在前。
2. 任何接口响应均不包含玩家 ID 或完整用户名。
3. Redis 停机时排行榜仍能从 MySQL 正常返回。
4. 未刮即丢弃的卡不会在历史记录泄露开奖结果。
5. 机器人中奖和未中奖均能被准确标记为自动操作。
6. PC 和移动端均可直接进入排行榜与记录。
