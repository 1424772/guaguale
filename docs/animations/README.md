## 全局实现约束

1. 购卡事务在服务端锁定结果与图案布局；前端动画只读取结果，不参与随机、判奖或兑奖。
2. 单个刮格默认在有效刮除面积达到 65% 时揭示；《放手一博》的单格阈值为 70%。达到阈值后补间清除剩余涂层，避免用户反复刮边角。
3. 多格卡可以逐格展示已刮开的内容，但只有全部必刮格达到揭示阈值后才播放整卡结果动画并进入“可兑奖/未中奖”状态。
4. 所有结果素材在开始刮奖前以相同策略预载；网络请求、资源尺寸、文件名和动画延迟不得向客户端提前泄露结果。
5. 任何结果动画都可以点击跳过；跳过、切换标签页、刷新或断线恢复不得改变卡片结果、刮开进度与兑奖状态。
6. 卡面不显示中奖概率。独立“规则详情”可展示与服务端一致的真实概率；动画不得制造虚假的擦边中奖结果。
7. 手动刮奖保留完整动画；机器人刮奖使用压缩动画，但兑奖金额和卡片状态机完全相同。《放手一博》禁止机器人刮奖。
8. 音效受全局静音开关控制，首次用户交互后才初始化音频；不使用现金到账、老虎机滚轮或催促倒计时音效。
9. 默认目标为桌面端 60 FPS、移动端不低于 30 FPS。连续 3 秒低于 30 FPS 时自动进入低性能模式，关闭模糊、折射和大粒子，仅保留位移、透明度与关键结果反馈。
10. 遵循 `prefers-reduced-motion`：关闭视差、抖动、镜头推拉和粒子，结果反馈缩减为 150–200 ms 淡入与清晰文字状态。
11. 动画文字、奖励金额、图案名称和结果状态由 HTML/CSS 层渲染；背景、纹理、装饰、图标和粒子素材分层，避免将功能文字烘焙进位图。
12. 动画结束事件只能推进表现层，不得直接发金币；兑奖必须调用服务端幂等接口成功后再更新余额。

## 共用状态机

`idle` → `scratching` → `cell_revealed` → `card_revealed` → `result_presented` → `redeemable | no_prize` → `redeeming | discarded`

- `idle`：卡片在桌面，可拖动、放入卡槽或开始刮奖。
- `scratching`：记录遮罩进度并持久化；动画可中断恢复。
- `cell_revealed`：单格达到阈值，只展示已公开内容。
- `card_revealed`：全部必刮格完成，前端请求/读取已锁定的最终结果状态。
- `result_presented`：播放对应档位动画；播放完成不是兑奖条件。
- `redeemable`：中奖卡可拖入兑奖区。
- `no_prize`：未中奖卡保留在桌面，直到进入垃圾桶。
- `redeeming`：服务端兑奖成功后播放收卡动画并移出桌面。

## 共用验收要求

- 自动化测试可将所有过场时长设为 0，仍能完成购卡、刮开、判奖和兑奖。
- 同一个 `cardId` 在不同设备恢复后，图案、奖励、刮开进度和状态一致。
- 未全部刮开时，不显示最终奖金，不播放最终档位专属音效。
- 动画被跳过或浏览器后台节流后，最终 UI 必须落在确定状态，不能卡在半透明遮罩或不可兑奖状态。
- 静音、低性能和减少动态模式均能独立启用，且不影响功能提示的可读性。
